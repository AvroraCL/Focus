# Focus 兼容性与限制说明

> 原则：不注入游戏进程、不挂钩图形 API、不绕过任何反作弊机制。覆盖层是独立的置顶透明窗口，帧数据来自系统级 ETW 事件。

## 显示模式

| 模式 | 覆盖层显示 | 帧采集 | 说明 |
| --- | --- | --- | --- |
| 窗口化 | ✅ 支持 | ✅ 支持 | 已验证（桌面应用） |
| 无边框窗口化（Borderless） | ✅ 设计目标 | ✅ 支持 | 主流游戏推荐模式；HUD 跟随游戏窗口或显示器 |
| 独占全屏（Exclusive Fullscreen） | ⛔ 首版不显示 | ✅ 支持 | 独占全屏由游戏直接接管显示输出，普通置顶窗口无法叠加。建议切换为无边框窗口化。 |
| 多显示器 | ✅ 已实现 | ✅ 支持 | 配置中可选择目标显示器；未选择时跟随游戏窗口所在显示器 |
| 高 DPI（125%/150%/200%） | ✅ 已实现 | ✅ 支持 | 按目标显示器 DPI 换算物理像素；已启用 PerMonitorV2 |
| HDR 游戏 | ⚠️ 未验证 | ✅ 支持 | HUD 颜色为 SDR 值，可能在高亮度 HDR 场景下偏暗/偏亮 |
| VRR / G-Sync / FreeSync | 不影响 | ✅ 支持 | 统计的是 Present 节奏，与刷新同步机制无关 |

## 帧数据

- 来源：`Microsoft-Windows-DxgKrnl` ETW 实时会话中的 Present 事件（D3D9/11/12、Vulkan、OpenGL 的 WSI 最终都经过该路径）。
- 需要**管理员权限**创建 ETW 实时会话。未提权时应用仍可运行，但 FPS/帧时间显示为不可用，并给出明确提示。
- 统计的是"提交的 Present"，与游戏引擎内部计数或显示端合成结果可能存在小幅差异。
- 同一进程的多个交换链（例如启动器窗口）会合并计入该进程；这与其他工具的默认行为一致。
- 与其它同样创建 ETW 会话的工具（RTSS、CapFrameX、PresentMon）可以并存，但多个工具同时挂载 DxgKrnl 时会增加系统开销。

## 反作弊

- Focus 不注入 DLL、不挂钩 Present、不读写游戏内存。
- 使用 ETW（系统内核事件）与一个独立顶层窗口。个别反作弊可能禁止任何置顶覆盖窗口或禁止 ETW 订阅；此类游戏请关闭 HUD 或不要在该游戏中使用本工具。
- 尚未在带反作弊的在线游戏中验证。

## 已知限制

1. 独占全屏不显示 HUD（见上）。
2. Windows 11 未测试；Windows 10 22H2 (19045) 已验证。
3. x64 平台；ARM64 未适配（.NET 可运行 x64 模拟，未测试）。
4. 覆盖层为分层 WPF 窗口，超大 HUD（数千像素）会提高 CPU 占用；建议保持 HUD 区域紧凑。
5. CPU 温度/功耗在部分平台需要内核驱动或管理员权限，缺失时显示 "—"。
6. 多显示器跨屏 HUD（单个 HUD 跨越两个显示器）不支持，请为每个显示器使用独立配置。
7. 游戏以管理员身份运行而 Focus 未提权时，覆盖层可能无法覆盖在游戏之上（完整性级别差异）。
8. 系统开启"专注助手"/全屏优化时，个别游戏的无边框窗口会被 DWM 特殊处理，覆盖层可能不显示。

## 建议的使用方式

- 游戏设置为**无边框窗口化** + 与桌面相同的分辨率，获得最佳兼容性。
- 以管理员身份运行 Focus（应用内提供"以管理员身份重启"）。
- 为每个游戏创建/绑定独立配置，Focus 会在检测到游戏时自动切换。
